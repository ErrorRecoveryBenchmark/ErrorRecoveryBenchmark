## Summary (English)

This document is the canonical technical reference for RecoverBench's data-generation pipeline (Chinese-language detail follows). Two stages:

1. **Human recovery demo collection.** From a `post_sim_state` (an error scene's stable post-injection state) and using SpaceMouse teleoperation of a Sawyer arm in MuJoCo + robosuite, an operator recovers and completes the task. Each demo passes two validation gates before inclusion: (a) the canonical task-success criterion (environment `_check_success()` held for 10 consecutive frames), (b) action-replay validation (reload the initial error state, replay recorded actions, confirm task success).

2. **MimicGen scene-configuration augmentation, RBG-aware.** Human demos are RBG-segmented into MimicGen-compatible subtask sequences (each Recovery Behavior Group has its own canonical subtask ordering). Within an RBG, demos can be re-targeted to new error scenes of the same subtype via MimicGen scene-configuration warping. Augmentation feasibility is preflighted on N=10 candidate scenes per subtype before bulk generation; only successful augmentations are retained.

**Why this design?** Naively collecting recovery demos for every (task × subtype) cell would require ~1,440 human demos. The RBG abstraction — errors within the same RBG share recovery motor primitives — reduces this to ~329 human demos (a **77% reduction**), with the remainder filled by augmentation. See [`../../INSIGHTS.md`](../../INSIGHTS.md) Finding 4.

For the user-facing benchmark framing, evaluation protocol, and headline findings, see [`../../README.md`](../../README.md), [`../../EVALUATION.md`](../../EVALUATION.md), and [`../../INSIGHTS.md`](../../INSIGHTS.md). The Chinese-language detail below is the implementation reference.

## 1. Overview

### 1.1 Purpose

This pipeline provides **recovery demonstration** data for VLA (Phoenix MCM + diffusion policy / Pi0.5 LoRA) fine-tuning. Starting from error scenes generated by v5, recovery demos are collected via human teleoperation, then expanded into large-scale training datasets using MimicGen-style augmentation.

### 1.2 Design Philosophy：Recovery Behavior Groups (RBG)

23 error subtypes × 6 tasks = 138 combinations; collecting separately for each would require 1,440 human demos. Using **Recovery Behavior Groups** , 23 subtypes are consolidated into 5 groups sharing recovery motor primitives：

- Subtypes within the same RBG share the same recovery subtask sequence
- Augmentation can transfer across subtypes within the same RBG (3C augmentation)
- Only representative demos need to be collected per group, greatly reducing manual effort

**Savings**：6 tasks total ~329 human demos (vs. naive 1,440 , saving 77%), after augmentation each subtype 100+ demos.

### 1.3 Relationship with v5 Pipeline

```
v5 Error Skill Pipeline (completed)
 → ErrorScene (JSON + NPZ): 130K validation + 1,304 training scenes
 ↓ (this pipeline uses training scenes as teleoperation starting points)
Recovery Collection & Augmentation Pipeline (this document)
 → Training data: MCM JSON + Diffusion HDF5
 ↓
VLA Training Pipeline (Pi0.5 LoRA / Phoenix)
```

### 2.3 Design Principles

1. **RBG -structured segmentation**：All recovery trajectories segmented by RBG-defined subtask sequences, enabling MimicGen-style object-centric warping per subtask
2. **Resumability**：manifest.json tracks progress, supports `--resume` to continue from interruption
3. **Validation gating**：Post-collection auto-verification of action replay consistency and augmentation feasibility; only augmentable demos count toward quota
4. **Dual-mode augmentation**：`faithful_mimicgen`（MimicGen WaypointTrajectory + env_interface） `legacy_replay`（closed-loop target_pose_to_action tracking）

## 3. Recovery Behavior Groups (RBG)

### 3.1 RBG Definitions

| RBG | Name | Description | Subtask Sequence | Subtypes |
|-----|------|------|-----------|----------|
| **RBG_A** | Re-grasp | Grasp misaligned, release and re-grasp | `retract → re_orient → re_grasp → re_lift → re_transport → re_place` | grasp_misalignment D0/D1, grasp_wrong_pose D0/D1 (4) |
| **RBG_B** | Retrieve | Object dropped, pick up and continue | `navigate_to_object → re_grasp → re_lift → re_transport → re_place` | drop_in_transit D0/D1, drop_at_wrong_place D0/D1 (4) |
| **RBG_C** | Retract | Collision occurred, back away and retry | `retract → navigate_to_object → re_grasp` | collision_holding/empty/eef_object/self × D0/D1 (8) |
| **RBG_D** | Redirect | Grasped wrong object | `release → navigate_to_object → re_grasp → re_lift → re_transport → re_place` | wrong_object D0/D1 (2) |
| **RBG_E** | Realign | Position error, correct and continue | `correct_position → resume_task` | trajectory_regression D0/D1, stuck_no_progress D0/D1, position_error D0/D1 (6) |

> **Total: 24 subtypes**

## 5. Stage 1: Human Teleoperation Collection

### 5.1 Prerequisites

1. v5 pipeline has generated training error scenes（`v5_training/{task}/scenes/` has JSON + NPZ files）
2. SpaceMouse or keyboard device (SpaceMouse recommended)
3. `recovery_collection.yaml` configured in demo_allocations
4. conda environment `mimicgen_env`（with MuJoCo 2.3.2 + robosuite）

### 5.2 Collection Workflow

```
1. Load config + task_registry
2. Load or create manifest.json
3. Create MuJoCo env + EnvWrapper
4. Create RecoverySegmenter (segmentation) + InjectionReplay (animation)
5. Create RecoveryDemoValidator (post-collection validation)
6. For each subtype:
 a. Load all error scenes for this subtype
 b. Loop until target demo count is reached:
 i. Select an error scene
 ii. [Optional] Play injection replayanimation (show operator how error occurred)
 iii. Scene stabilization (Stack task: wait until object velocity < threshold)
 iv. Human teleoperation (SpaceMouse/keyboard control)
 v. Success verification (check_success() consecutive 10 frames)
 vi. Save RecoveryDemo NPZ + update manifest
 vii. Post-collection validation:
 - action replay: reload initial state → replay actions → check success match
 - scene aug preflight: test augmenter on N target scenes
 viii. Determine whether to count toward progress based on quota_rule
 c. Failed scenes can be retried (max_retries_per_scene=3)
```

### 5.3 animation

`injection_replay.py` 3 Stageanimation，：

1. **Context **：frames 0 frames N（execution）
2. **Re-inject**：Re-execute using saved seed Error Skill `inject()`
3. **Pause**：Pause 1.5 seconds to let operator observe final error state

Configuration：`replay_animation.speed=1.0`, `context_frames=50`, `pause_after=1.5`

### 5.4 Scene stabilization

`mimicgen_source_validation.py` in `settle_scene_for_source_collection()` ensures scene objects are at rest：
- Loop `mj_step()` until all object linear velocity < 0.01 m/s and angular velocity < 0.05 rad/s
- Wait up to `max_settle_steps=40` steps
- If timeout or scene already satisfies `check_success()`，reject the scene

 Stack task（）。

### 5.5 Post-collection validation

`recovery_collection_validation.py` performs on each successful demo：

| Check | Method | Purpose |
|------|------|------|
| **Action replay** | Reload initial state → replay actions → compare success | Confirm action sequence is reproducible |
| **Scene aug preflight** | Run augmenter on N=10 target scenes | Predict augmentation feasibility |

**Quota rules** (`quota_rule`)：
- `augmentable_only`（default）：Count toward target only when at least one augmentation scene succeeds
- `replay_only`：Count only when action replay succeeds
- `success_only`：All successful demos count (no validation)

## 7. Stage 2: Recovery Trajectory Segmentation

### 7.1 Segmenter Architecture

`RecoverySegmenter` **mode**： demo RBG Method。

| RBG | Method | Segmentation Logic |
|-----|------|---------|
| RBG_A | `_segment_regrasp` | retract(EEFdisplacement>5cm) → re_orient(EEFnear object<6cm) → re_grasp(gripper closed>0.05) → re_lift(Z>0.84m) → re_transport → re_place |
| RBG_B | `_segment_retrieve` | navigate_to_object(EEF→<6cm) → re_grasp() → re_lift(Z>0.84m) → re_transport → re_place |
| RBG_C | `_segment_retract` | retract(displacement>5cm) → navigate_to_object |
| RBG_D | `_segment_redirect` | release(gripper open<0.02) → navigate_to_object → re_grasp → re_lift → re_transport → re_place |

### 8.2 Scene augmentation (3A) — Core Algorithm

 ErrorScene，, demo **object-centric warping** to the new scene：

```
For each target_scene:
 1. ErrorSceneVariantGenerator generates scene variants:
 - Use placement_initializer to resample object positions
 - Anchor (anchor) 、position 、
 - Add Gaussian noise (position_noise_std=0.005)
 - Verify variant does not satisfy check_success() (completedtask )

 2. set_sim_state_flat(variant.sim_state) → environment

 3. For eachtask (Sort by RBG Definitions ):
 a. Query current object pose (4×4)
 b. task:
 - nearest_neighbor_object: weighted distance(pos_weight×position+rot_weight×rotation), k=3 random select
 - random: random select
 c. Build source segment: src_eef_poses + gripper_actions
 d. Object-centric warping:
 transformed_eef = T_relative @ src_eef
 T_relative = target_obj_pose @ inv(src_obj_pose)
 e. Interpolate from last waypoint to warped segment
 f. execution WaypointTrajectory:
 For each waypoint:
 action_pose = env_interface.target_pose_to_action(pose)
 play_action = [action_pose, gripper_action]
 env.step(play_action) → 

 4. check_success() → results
```

### 8.3 Cross-degree augmentation (3B)

- **error description**：TypeDefinitions Description（13 ）
- **motion instruction**：Based on (RBG, subtask_label) Mapping 28 motion codebook 
- **Sampling rate**： 4 steps（camera）
- **image**：224×224 RGB，agentview camera

### 9.2 Diffusion Training data (4B)

 HDF5 Training data：

| Parameter | Value |
|------|-----|
| Raw frequency | 20 Hz |
| Downsampling | 5 Hz (ratio=4) |
| Action chunk length | 12 steps |
| image | 224×224 |

**Processing workflow**：
1. 20Hz actions → 5Hz Downsampling
2. Create overlapping action chunks：`chunks[i] = actions[i:i+12]`
3. steps motion label（Based on (RBG, subtask_label) → codebook index）
4. Save as HDF5：`action_chunks`, `motion_labels`, `images`

## 11. Troubleshooting

| Problem | Cause | Solution |
|------|------|---------|
| SpaceMouse not responding | udev rules not active | `sudo udevadm control --reload-rules && sudo udevadm trigger`，unplug and replug |
| Render window black screen | MUJOCO_GL set incorrectly | Confirm `MUJOCO_GL=glfw`（not `egl`） |
| EnvironmentMismatchError | MuJoCo version mismatch | Install MuJoCo 2.3.2: `pip install mujoco==2.3.2` |
| Missing post_sim_state in NPZ | Old version NPZ file | Load `sim_state` |
| Recovery demo missing target_poses | Old collection script did not record | Run `backfill_recovery_target_poses.py` |
| No target scenes found | --scenes_dir path incorrect | Confirm `v5_training/{task}/scenes` |
| Scene aug success rate is low | Object ref resolution failed | Check scene JSON in `labels.target_object` Field |
| Stack scene rejected: unstable_start | Objects not yet at rest | Adjust `max_settle_steps` or settle threshold |
| Missing prepared MimicGen source | The augmenter env_interface | Confirm `mimicgen_success/prepared_source/{task}_src.hdf5` exists |
| Demo not counting toward target | quota_rule=augmentable_only | Check `human_demo_test_report.json` in aug_preflight results |
| Collision-type augmentation NaN actions | warping Value | Lower `position_noise_std` orCheck |
